# 批量验证 第一波: 需求清单(冻结)

**规矩**: 需求先于工厂能力写下并冻结。写式样书时如果工厂表达不了,记成"缺口",不改需求迁就工厂。
领域: 电商订单(shop)。表: customers / products / product_prices(价格历史,只追加) / orders / order_items。

| # | 需求(业务语言) | 事前预测 |
|---|---|---|
| R1 | 客服按顾客 id 查看顾客信息(名字、邮箱、会员等级、注册时间) | 现有模式 get_by_id |
| R2 | 仓库扫码,按 SKU 查商品(名称、分类、状态) | 现有模式;键不是 id,看命名约定 |
| R3 | 订单一览: 可按顾客、状态、下单期间筛选,新的在前,分页 | 现有模式 list_keyset |
| R4 | 商品一览: 按分类、状态筛选,并可按商品名**前缀**搜索,分页 | 缺口: prefix 运算符 |
| R5 | 某个订单的明细一览,按行号升序 | 现有模式;排序键只在订单内唯一 |
| R6 | 某商品在**某个时点**的有效价格(价格表只追加,valid_from 生效) | 缺口: 版本化主数据(as-of) |
| R7 | 某顾客在期间内的订单统计: 件数、金额合计、平均单价、取消率 | compute |
| R8 | 订单详情: 订单头 + 全部明细一起返回 | 缺口: 多表 |
| R9 | 日别销售额报表(期间内每天的订单数和金额) | 缺口: 聚合 GROUP BY |
| R10 | 发货延迟告警: 截至某时点,下单超过 N 天仍未发货的订单 | 缺口: 派生条件(as_of - N 天) |

每个 API 记录: 审查(轮数/发现)、一次通过、AI 耗时、逃生口、发现的工厂缺口。
人工成本: 第一波由 Claude 写(初步基准),之后由人按同样需求写 2~3 份量真实耗时。
