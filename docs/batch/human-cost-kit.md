# 人工成本测量: 请按下面的步骤写 3 份式样书

第一波的结论是"人的成本主要花在做业务决定上,而不是写 YAML"。这个只有人来写才测得出。
3 个需求都是**新的**(第一波没有做过),所以不能照抄现有的式样书。可以参考现有式样书的写法。

## 需求(shop 领域,表已经存在: db/schema/shop.sql)

| # | 需求 | 类型 |
|---|---|---|
| H1 | 客服按邮箱地址查顾客(和 GetCustomer 一样的信息) | 模式 API |
| H2 | 某个商品的价格历史一览: 生效时间新的在前,可按生效期间筛选,分页 | 模式 API |
| H3 | 顾客等级分布: 某个注册期间内注册的顾客,各等级的人数,以及金卡会员的占比 | compute(AI 写逻辑) |

## 步骤(每个需求都一样)

1. **开始计时**
2. 在 `proto/factory/shop/v1/shop.proto` 加 rpc 和 message(注意 `buf.validate` 规则)
3. 写 `specs/shop/<名字>/spec.yaml`(参考同类型的现有式样书)
4. 运行 `make loop SPEC=specs/shop/<名字>/spec.yaml`
5. 审查挡下时: 做决定 → 改式样书或写进 `review_decisions` → 回到 4
6. 流水线全绿时**停止计时**

## 提示

- 命名约定: 字段名 = 列名 → `=`;`<x>_after` / `<x>_before` → `<x>_at` 的 `>=` / `<`;`<x>_prefix` → 前缀匹配;`<单数表名>_id` → `id`
- 自动生成的验收已经覆盖了机制(筛选、排序、翻页、校验边界),人写的用例只需要写**业务意图**
- `go run ./factory/cmd/factory review-prompt specs/shop/<名字>/spec.yaml` 可以看到审查员看到的全部内容
