## P1: 接线层模块化

现状(E 步实测): 新种类第一次出现时要改的地方

| 种类 | 要改的层 |
|---|---|
| 类型(日期 / 十进制) | 设计语言的类型表、proto 校验规则、例子的值、编译器的类型对照、适配器的转换、validation 边界值、差分的值域 / 表示、gen/db 的 Go 类型 |
| 出口(多条) | spec 的模式校验、设计语言的写法、响应的形状、IR、流水线部件、handler 模板、差分的期待值 |
| 来源(JSON版本) | 领域的写法、catalog 注入、来源部件、验收数据的转换、差分的数据生成 |

做法: 每个种类**一个文件**,实现一个接口;各层只查注册表,不再出现 `if kind == "date"`。

- `types/`: 中文名 / proto 类型和校验 / 核心类型 / Go 类型和转换 / 例子的值 / 边界值 / 差分的值域、不存在的值、表示
- `exits/`: 中文写法和参数 / 响应的形状 / 流水线部件 / handler 模板 / 差分的期待值和出口用例
- `sources/`: 领域的写法 / 逻辑表的列 / 来源部件 / 验收数据怎么写进物理表 / 差分的数据生成

验证: 重构前后生成的代码 diff 为空、验收 / 变异不变;然后加两个新种类实测
(类型 `时刻`(time of day)、出口 `前N条`(排序 + 取前 N 条,试用里 2 个 API 需要)),每个只加一个文件。

### P1 的结果(2026-11-17)

| 种类 | 以前(E 步实测) | 现在 |
|---|---|---|
| 新类型 | 日期 / 十进制: ~90 行,改 6~8 个文件 | 邮编: 1 个文件(注册表一次性加了"继承"和"格式 → 值域") |
| 新出口 | 多条: ~155 行,改 7 个文件 | 前N条: 2 个文件(定义 85 行 + Go 7 行),单元库 0 改动(复用 多条 的套装) |
| 新来源 | JSON版本: ~500 行,改 6 个文件 | 集中到 sources/json_versions.go;第三种来源还没有实测 |

重构前后: 生成物不变(只有 ::bigint → ::int8 和覆盖说明的文字),验收 / 变异 / 元件认证不变;试用分支 953 个验收全过。
顺带修正: stats 和 validation 漏了「多条」;分页出口用例的取值改为来源部分的行;注册表不依赖文件的初始化顺序。

### P2 的结果(2026-11-17)

对策都是结构性的(确定性的用例),不是调随机参数:
- **扫值请求**: 每个筛选参数单独取它的列出现过的值(最多 5 个)、同一行的全部参数、两两组合、不存在的值;
  前缀参数取陷阱前缀(% _ 在开头 / 中间 / 结尾);多版本来源加"只在旧版本里出现的值"
- **出口用例**: 单条 3 个不同的不存在的键;分页 不传 page_size / page_size = 0 / 不传翻到第 2 页;途中改条件每个参数各一次(最多 3)
- **多版本来源的数据**: 和常量比较的列(删除值 / 逻辑删除值)按 1/3 注入;自然键的值域扩大;
  覆盖条件加"多出来的旧版本 ≥3、最新是删除的键 ≥3"(参考求值器跑来源部分算出来)

| 变异 | 以前 | 现在(3 个种子里最少) |
|---|---|---|
| page_size 默认值 | 1 | 12 |
| NOT_FOUND → INTERNAL | 1 | 4 |
| % 的转义 | 1 | 4 |
| 小数按文本比较 | 1 | 3 |
| token 不绑定条件 | 1 | 3 |
| 逻辑删除 | 2 | 10 |

代价: 差分用例 451 → 约 750;验收时间 5 秒 → 6 秒(本地实测)。

**第二轮(试用分支暴露的)**: 试用的复合键 / 每组取一条 / 有效期的 API 上,margin 在某个种子下又出现 0 和 2。
单靠"多造请求"解决不了,最后的通用机制是:
- **条件的敏感度**: 每个筛选条件和条件里 and 的每一项,用参考求值器换成恒真,结果变了的请求要 ≥3。
  这一条覆盖了"不看有效期的结束日""筛选条件被忽略"以及以后的任何新单元,不需要逐个元件写规则
- **覆盖条件驱动的重生成**: 先用参考求值器预估覆盖(不要服务器),不满足就换派生种子重新生成数据(最多 5 次,可复现)
- 每组取一条的分组列值域缩小(组里要有多个候选);多列单元按行锚定边界(结束日 / 结束日 + 1);
  自然键只在组合少时扩大;删除的注入 1/6
- margin 本身: 有变异没执行(替换式没命中 / 执行器偶发出错)也算失败

结果: main(33 个变异)和试用分支(35 个)在 3 个种子下,差分最少都是 3。

### P3 的结果(2026-11-17)

`scripts/matrix.py` 生成 来源(普通的表 / JSON版本)× 分库 × 出口(单条 / 一览 / 多条 / 前N条)× (筛选单元, 类型) 30 对 × 必填 / 可选,
另加 没有输入 / 枚举 / 枚举的列表 / 复合主键 / 每组取一条 / 输入之间的规则,共 21 个 API。`scripts/matrix.sh` 在临时工作区里跑整条流水线。

| 轮 | 发现 | 种类 |
|---|---|---|
| 1 | 分页的排序列可能为空 → 编译器的内部错误(step 11 tuple_after …),设计者看不懂 | 设计语言的报错 |
| 1 | 日期的列表参数(属于)适配器不支持 | 适配器 |
| 2 | **分库 + 分页不选库**(分页的 handler 写死 h.q,一直查主库) | **适配器的 bug** |
| 2 | 参考求值器把所有分库的行合在一起选版本(版本的选择在各个库里分别进行) | 差分的模型 |
| 2 | 邮编(带格式的类型)的前缀匹配: 前缀永远通不过格式校验,条件永远不起作用 | 设计语言的语义 |
| 3–6 | 必填的等于条件 / 分库键的列太分散;自然键扩大的倍数;删除值的注入叠加;时间参数的必填判断(message 的 presence);来源没有行;出口要的数据(按截取前的行数);条件严格时数据量不够 | 差分的数据生成 |
| 第二代 | 枚举的列表参数(属于)适配器不支持 | 适配器 |

第二代只发现 1 个 → 收敛。差分的数据生成最后的形状: 扫值 + 最宽的请求 + 覆盖条件(含条件的敏感度、出口要的数据)驱动的重生成(换种子、数据加倍)。

**还没有覆盖的组合**(下一代矩阵的候选): 计算(要 AI)、自定义、逃生口 SQL、输出的类型转换(输出名和列名不同)、
很多列的表(性能)、分库键不是整数。
